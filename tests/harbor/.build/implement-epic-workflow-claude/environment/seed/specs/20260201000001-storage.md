# Feature: 20260201000001-storage

## Overview

Persist the todo list to a JSON file so todos survive between runs of
`python3 -m todo`. Today nothing is stored. The commands spec builds on this
module.

## Requirements

- [ ] **Load todos from a JSON file**
  `todo.storage.load()` must return the todo list from the file named by the
  `TODO_FILE` environment variable, or from `~/.todo.json` when it is unset
  or empty.

- [ ] **Treat a missing file as an empty list**
  Loading when the file does not exist must return `[]` and create no file.

- [ ] **Save atomically**
  `todo.storage.save(todos)` must leave either the old file or the complete
  new one on disk, never a partial write.

- [ ] **Store each todo as id, title and done**
  Every stored todo is a JSON object with an integer `id`, a string `title`
  and a boolean `done`, and `load()` returns them as plain dicts.

## Constraints

- Standard library only; Python 3.12.
- Only `todo/storage.py` and new test files under `tests/` change.

## Acceptance Criteria

- [ ] **Round trip**
  Saving a list and loading it again returns an equal list.

- [ ] **Missing file**
  Loading from a path that does not exist returns `[]`.

- [ ] **Override path**
  With `TODO_FILE` set, load and save use that path and never touch
  `~/.todo.json`.

## Technical Approach

- Write to a temporary file in the target's directory, then `os.replace` it
  over the target.
- Unit tests use `unittest` in `tests/test_storage.py`.

## Success Metrics

- `python3 -m unittest discover -s tests` passes.

## Non-Goals

- Concurrent writers.
- Any format other than JSON.
