# Feature: 20260101000002-commands

## Overview

Give `python3 -m todo` its first commands, `add`, `list` and `done`, so a
user can actually manage a todo list from the terminal. The commands read
and write todos through the storage module from the storage spec.

## Requirements

- [ ] **Add a todo**
  `todo add <title>` must store a new, not-done todo and print its id.

- [ ] **List todos**
  `todo list` must print one line per todo showing its id, a done marker and
  its title, in id order.

- [ ] **Complete a todo**
  `todo done <id>` must mark that todo done.

- [ ] **Reject an unknown id**
  `todo done` with an id that does not exist must print an error to stderr
  and exit with status 1.

## Constraints

- Must read and write todos only through the storage module's `load()` and
  `save()`.
- Standard library only.

## Acceptance Criteria

- [ ] **Add then list**
  After `todo add "buy milk"`, `todo list` shows a not-done "buy milk".

- [ ] **Done**
  After `todo done 1`, `todo list` shows todo 1 as done.

- [ ] **Unknown id**
  `todo done 99` on a list without id 99 exits 1 and writes to stderr.

## Technical Approach

- Subcommands built with `argparse` subparsers in `todo/cli.py`.
- New ids are one more than the highest existing id.

## Success Metrics

- Every acceptance criterion is covered by a test that passes.

## Non-Goals

- Deleting or editing todos.
- Help text beyond what argparse generates (covered by the help spec).
