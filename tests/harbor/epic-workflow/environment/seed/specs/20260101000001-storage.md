# Feature: 20260101000001-storage

## Overview

Persist the todo list to a JSON file so todos survive between runs of
`python3 -m todo`. Today nothing is stored. This is the foundation the
commands spec builds on.

## Requirements

- [ ] **Load todos from a JSON file**
  The system must read the todo list from `~/.todo.json`, or from the path in
  the `TODO_FILE` environment variable when it is set.

- [ ] **Treat a missing file as an empty list**
  Loading when the file does not exist must return an empty list, not an
  error.

- [ ] **Save todos without risking a half-written file**
  Saving must leave either the old file or the complete new one on disk,
  never a partial write.

- [ ] **Store each todo's id, title and done state**
  Every stored todo must carry an integer `id`, a string `title` and a
  boolean `done`.

## Constraints

- Standard library only; no third-party packages.
- Must run on Python 3.12.

## Acceptance Criteria

- [ ] **Round trip**
  Saving a list and loading it again returns an equal list.

- [ ] **Missing file**
  Loading from a path that does not exist returns `[]`.

- [ ] **Override path**
  With `TODO_FILE` set, load and save use that path and never touch
  `~/.todo.json`.

## Technical Approach

- A `todo/storage.py` module exposing `load()` and `save(todos)`.
- Write to a temporary file in the same directory, then rename it over the
  target.

## Success Metrics

- Every acceptance criterion is covered by a unit test that passes.

## Non-Goals

- Concurrent writers from several processes.
- Any storage format other than JSON.
